## Implementation Integrity

## สิ่งที่พบและแก้แล้ว

P0: 0, P1: 1, P2: 3, P3: 0

### [P1] สีข้อความเดิมไม่ผ่าน contrast สำหรับข้อความทั่วไป

- ตำแหน่งเดิม: `shared.jsx:85–97`, `styles.css:144` ใน commit อ้างอิง
- ด้าน: Accessibility; WCAG 1.4.3
- หลักฐาน: ข้อความ 14px สี `#188038` บน `#E6F4EA` ได้ประมาณ **4.42:1** ต่ำกว่า 4.5:1
- ผลกระทบ: ข้อความยืนยันรายการอ่านยากขึ้น โดยเฉพาะสายตาที่ต้องการ contrast สูง
- แก้: พื้นขาว `#FFFFFF`, ข้อความ `#202124` ได้ประมาณ **16.10:1**; สีเขียวใช้กับไอคอนแทน ปุ่มปิด `#596579` บนขาวได้ **5.90:1**
- แนวทาง: `$impeccable colorize` → `$impeccable polish` — ดำเนินการแล้ว

### [P2] ตำแหน่งแจ้งผลทับเมนูด้านบน

- ตำแหน่งเดิม: `styles.css:144` (`top:16px; right:16px`)
- ด้าน: Responsive / Implementation Integrity
- หลักฐาน: ภาพผู้ใช้แสดงกล่องทับบริเวณ account/navigation; header เดิมสูงอย่างน้อย 76px
- ผลกระทบ: ข้อมูลชั่วคราวแย่งพื้นที่ควบคุมหลักหลังทำรายการ
- แก้: มุมล่างขวา 24px บน desktop; มือถือเว้นด้านข้าง/ล่าง 16px และคำนึง safe area ข้อความยาวตัดบรรทัดได้
- แนวทาง: `$impeccable layout` / `$impeccable adapt` → `$impeccable polish` — ดำเนินการแล้ว

### [P2] เวลาซ่อนไม่หยุดเมื่อกำลังอ่านข้อความ

- ตำแหน่งเดิม: `ParcelHubApp.jsx:62–65`
- ด้าน: Accessibility / Interaction; ไม่อ้างว่าเป็น WCAG timing violation เพราะเป็นข้อมูลสำเร็จที่มีประวัติรายการให้ตรวจต่อได้
- หลักฐาน: timeout 6 วินาทีไม่มี hover/focus pause
- ผลกระทบ: ผู้ใช้ที่กำลังอ่านข้อความหรือกำลังจะปิดด้วยคีย์บอร์ดอาจถูกซ่อนข้อความกลางทาง
- แก้: Banner ดูแลเวลาที่เหลือ หยุดเมื่อ hover หรือ focus และนับต่อเมื่อออกจากทั้งสองสถานะ; notification id ทำให้ข้อความซ้ำเริ่มเวลาใหม่ และ cleanup เมื่อ unmount
- แนวทาง: `$impeccable harden` → `$impeccable polish` — ดำเนินการแล้ว

### [P2] สร้าง status region พร้อมเนื้อหาในครั้งเดียว

- ตำแหน่งเดิม: `shared.jsx:85–97` ที่ return null ก่อนมีข้อความ
- ด้าน: Accessibility; ความเสี่ยงต่อการประกาศข้อความ ไม่ยืนยันว่า screen reader รุ่นใดล้มเหลว
- หลักฐาน: ตัว region ไม่มีอยู่ก่อนข้อความเข้ามา จึงพึ่งพาการตรวจ insertion ของแต่ละ assistive technology
- แก้: คง region ว่างไว้ก่อนข้อความเข้า ใช้ `role="status"`, `aria-live="polite"`, `aria-atomic="true"`; ปุ่มปิดอยู่แยกจาก region และไม่มีการย้าย focus อัตโนมัติ
- แนวทาง: `$impeccable harden` → `$impeccable polish` — ดำเนินการแล้ว; ยังต้องตรวจการประกาศด้วย screen reader จริงก่อนอ้าง conformance

## การออกแบบและสิ่งที่รักษาไว้

ลดพื้นที่สีเขียวทั้งกล่องให้เป็นไอคอนสำเร็จขนาดเล็ก ใช้พื้นขาวและเงาเดิมเพียงอย่างเดียว ข้อความสั้นหนึ่งชุด ไม่มีหัวข้อหรือคำอธิบายเพิ่ม รักษาข้อมูลจำนวนรายการและเลขห้อง ชื่อปุ่มปิด และการแจ้งผลเฉพาะเมื่อบันทึกสำเร็จ ข้อผิดพลาดยังอยู่ใกล้การทำรายการเดิม

ปัญหาเป็นข้อบกพร่องเฉพาะจุด ไม่ใช่ความจำเป็นต้องเปลี่ยน identity ทั้งเว็บ สีและ typography เดิมยังคงใช้ได้ การจับเวลาถูกย้ายจาก app มารวมกับ component แจ้งผล เพื่อลดความซ้ำซ้อนของการดูแล lifecycle

# 2026-11-01 — Admin tools: Staff registration and Resident directory CSV import

Branch `requirement-doc` (after merging `main` up to PR #35). Backlog **US-28** and **US-29**.
Scope change: both are outside the four core features, so **advisor sign-off is pending**.

## Why

Staff accounts and the Resident directory could only be created by the dev seed tool
(`cmd/seed`), which also writes fake data and refuses to run in production. The system therefore
could not be handed over to a real dormitory, and nothing kept the directory current as Residents
moved in, changed rooms or moved out, even though Check-In validates every room against it.

## What changed

**Staff registration (US-28)**
- `POST /api/v1/admin/staff`, `GET /api/v1/admin/staff`: Admin only (RBAC at the API).
  Role `operator` (shown as Staff) or `admin`. Username 3-32 of `a-z 0-9 . _ -`, password 8-72
  bytes (bcrypt). 409 `USERNAME_TAKEN`.
- Migration `0009`: `staff.created_by` records which Admin registered the account.
- `backend/cmd/createadmin`: creates the first Admin at install time (production-safe, unlike
  seed). Added to both Dockerfiles.
- Frontend: `StaffPage.jsx`, nav item **ลงทะเบียนผู้ใช้** (Admin only).

**Directory import (US-29)**
- CSV `room_number,full_name,phone` (`room_number` = building + 3-digit room, e.g. `1101`).
  The file is the full current list: same name and room = unchanged; same name in exactly one
  other room = moved; new name = added; active Resident missing from the file = moved out
  (`is_active = false`, never deleted).
- `POST /admin/residents/import/preview` (dry run), `POST /admin/residents/import` (one
  transaction; any error line → 422 `RESIDENT_IMPORT_INVALID`, nothing applied),
  `GET /admin/residents/export` (same format, UTF-8 BOM for Excel).
- Missing rooms and buildings are created and listed in the preview. Moved or moved-out Residents
  with Pending Parcels are flagged.
- Phone numbers that Excel stripped of their leading 0 (8-9 digits, not starting with 0) get the
  0 back.
- Migration `0010`: table `resident_imports` (who applied each import, when, counts).
- Frontend: `ResidentsPage.jsx`, nav item **จัดการผู้พัก** (Admin only). The page shows the
  column format and rules before upload, plus template and current-list downloads.

Existing screens, tokens and copy are unchanged apart from the two Admin-only nav items.

- Residents are matched by full name; a spelling change reads as move-out + new Resident (visible in

- A moved Resident's Pending Parcels stay under the old room.

## OWASP Top 10 review (same day, after merging `main` PR #36-#38)

Source review of the branch (no live probing). Two fixes; everything else held up (RBAC at the API,
parameterised SQL, bcrypt, HMAC sessions with server-side revocation, login throttling, JSON-only
bodies + SameSite=Lax against CSRF, push endpoint allowlist against SSRF, access logs).

- **A01, Medium (fixed):** push registrations belong to a room and last 180 days, and the CSV import
  deactivated leavers without revoking them. A former Resident's phone kept getting the room's
  notifications and could read its Pending Parcels via `/resident/me`. The import now revokes every
  registration of a room someone leaves (moved or moved out), in the same transaction, attributed to
  the importing Admin; queued notifications are cancelled. The preview shows the device count
  (`pushDevicesRevoked`). Test: `TestResidentImportRevokesPushInVacatedRooms`.
- **A03, Low (fixed):** the public room claim (`POST /resident/otp`) used the typed room in `ILIKE`,
  so `%`/`_` could probe which rooms exist. Now an exact case-insensitive match. Test cases added to
  `TestPush_ClaimValidationAndRateLimit`.
- **To check at deployment:** `sslmode=disable` is fine only while the DB sits on the same Docker
  network; HSTS/CSP/`X-Frame-Options` should be set at the proxy (framing is already harmless for
  the Staff UI because the Lax session cookie isn't sent in cross-site frames).

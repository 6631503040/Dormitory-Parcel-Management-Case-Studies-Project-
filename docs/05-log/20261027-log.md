# 2026-10-27 — LINE removed; Resident page is the notification channel

Follow-up to `20261021-web-push-notifications.md`. The team confirmed LINE is no longer used: Residents
use a separate web page (`/resident/`) to check whether a Parcel has arrived and to receive a phone
notification. Scope change (Epic E3 pull → push) is still **pending advisor sign-off**.

## Logic change — Resident status page refreshes itself

Before: the status view only reloaded on open or when the Resident tapped "รีเฟรช". A Check-Out sends no
push, so a Picked Up Parcel stayed on an open page indefinitely.

Now (`src/resident/ResidentApp.jsx`, `public/resident/sw.js`):

| Trigger | Why |
|---|---|
| Service worker posts `{type: "parcel_arrived"}` to open `/resident/` windows after showing a push | New Check-In appears at once while the page is open |
| `visibilitychange` → visible | Returning to the app shows current data |
| Every 30 s while visible | Picks up Check-Out (no push for pickups) |

Background reloads are silent; the page shows "อัปเดตล่าสุด <time>"; the manual button stays.
Tests: two new cases in `ResidentApp.test.jsx` (foreground reload, service-worker message).

## Edit a checked-in Parcel (US-26)

Request: an edit button for Parcels already checked in. Treated as the correction step of Check-In
(in scope), not a new feature area.

- UI: "แก้ไข" button in the Parcel History modal (opened by clicking any row on Dashboard / Archive),
  shown only for **Pending Parcels with a room**. Form: Tracking Code, Room Number (directory
  combobox), note. Only changed fields are sent. The history shows each edit as "field: before → after".
- API: `PATCH /api/v1/parcels/:trackingCode` → `store.EditParcel` (row lock, diff, `edited` event with
  `changes.{trackingCode,room,note}.{from,to}`). Picked Up / unmatched → 409 `PARCEL_NOT_PENDING`;
  duplicate code → 409 `DUPLICATE_TRACKING_CODE`; unknown room → 422.
- A room change drops a recipient who isn't in the new room, queues a push for the new room; the old
  room's queued push no longer counts the Parcel (cancelled if it was the only one).
- Migration `0006_parcel_edit_event.sql` adds enum value `edited`.
- Tests: `api/parcel_edit_test.go` (2), `TestPush_EditedRoomNotifiesNewRoomOnly`,
  `ParcelHistoryModal.test.jsx` (+3).
- Any signed-in Staff (operator or admin) may edit — every edit is attributed in the audit trail.

## Dashboard summary board (day / week / month)

- UI: `components/SummaryBoard.jsx` replaces the one-line "วันนี้ · รับเข้า · นำออก · รอรับ" on the
  Dashboard: 3 cards (พัสดุเข้า / พัสดุออก / รอรับในระบบ), period tabs วัน / สัปดาห์ / เดือน, ‹ › to
  step through periods (› disabled on the current one), "กลับไป…นี้" to return. Mobile: cards stack.
- API: `GET /dashboard?period=day|week|month` (default day, so old callers are unchanged); response
  adds `period`, `from`, `to`. Week = Monday–Sunday, month = calendar month, Asia/Bangkok.
- Definitions: received / picked up = within the period; waiting = balance at the period's end. For
  the current period the card also says how many unmatched Parcels the total includes — that is why it
  can be higher than the Pending list under it (unmatched Parcels live in their own queue).
- Verified in the real app (Chrome, somsri): Sep 2569 ended with 409 waiting; Oct: +58 in, −25 out →
  442 now = 417 in the list + 25 unmatched.
- Tests: `TestDashboardCounts` (+ week/month ranges, Sunday, February, invalid period, back-dated
  Parcel), `SummaryBoard.test.jsx` (5).

## Check-Out no longer requires a room

- Migration `0007_checkout_without_room.sql` drops CHECK `parcels_roomless_is_pending`;
  `store.CheckOut` no longer filters `room_id IS NOT NULL`. A roomless Parcel keeps its
  `unmatched_reason` and note after pickup and leaves the unmatched queue.
- Assign Room on a roomless Parcel that was already handed over now answers 409 `PARCEL_NOT_PENDING`
  (was the misleading `PARCEL_HAS_ROOM`).
- Check-Out modal: no more "กรุณาจัดห้องก่อนนำออก" block; shows "ยังไม่ระบุห้อง" and "พัสดุไม่มีเลขห้อง —
  ตรวจสอบชื่อผู้รับกับฉลากพัสดุก่อนส่งมอบ", no room list.
- Verified in the real app: SPX4028530443 (no room) checked out by Somsri; unmatched count 27 → 26;
  history shows รับเข้า (Prasert) → นำออก (Somsri), chip นำออกแล้ว, no edit button.
- Tests: `TestCheckOutParcelWithoutRoom` (new), `TestUnmatchedParcelLifecycle` and
  `TestDatabaseEnforcesInvariants` updated; Check-Out modal test rewritten.

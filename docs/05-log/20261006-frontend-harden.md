## Error prevention implemented

- Room/name lookup and tracking-code scan are separate. Selection requires an exact full code submitted with Enter; wrong-room, unknown, already-collected and repeat scans cannot add an incorrect selection.
- Checkout stays within one room, shows all selected records across pages, asks before changing a room with selections and confirms room/count before Check Out All. Parent commit revalidates current IDs, room and status; repeated submission is guarded.
- Check-In keeps parent-controlled drafts when its dialog closes. Duplicate codes, rooms absent from the existing mock directory, incomplete next parcels and missing damage reasons block saving. Associated field errors focus the field needing correction. Retaining a room alone does not create a phantom next parcel.
- Closing or refreshing a page with a draft triggers the browser's leave warning; logout explicitly asks before discarding it. Drafts are in memory, not persistent across page refresh or browser close.
- Explicit persistence writes occur before success feedback/state changes. Malformed existing storage is retained and blocks overwrite; empty saved lists stay empty. Blocked/quota failures preserve prepared data. Raw storage comparison prevents overwriting changes from another tab.
- Directory-resolved displayed resident names are searchable. Dates render explicitly in Asia/Bangkok; legacy offset-free datetime values are interpreted as Bangkok wall time, without changing stored raw values.
- Identity confirmation retains physical damage flags/reasons. Long codes/names wrap, table and checkout lists paginate at 25, and interactive field boundaries use the existing muted palette color for visibility.
